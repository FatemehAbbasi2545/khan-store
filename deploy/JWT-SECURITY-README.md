# جلوگیری از جعل توکن با کلید پیش‌فرض

از `khan-store-backend-jwt-security-fix.zip` برای اپ بک‌اند لیارا استفاده کنید. این فایل کل کد بک‌اند و همه اصلاحات قبلی پرداخت، حریم خصوصی سفارش، ورود اجباری و مالکیت سبد را هم دارد. `khan-store-backend-latest.zip` کپی همین نسخه است. فرانت‌اند در این مرحله تغییر نکرده است؛ آخرین نسخه آن login-checkout است.

## تنظیم لازم پیش از انتشار

در پنل لیارا، اپ بک‌اند ← تنظیمات ← متغیرهای محیطی، مقدار `ADMIN_JWT_SECRET` باید یک مقدار تصادفی و اختصاصی حداقل ۳۲ کاراکتری باشد. برنامه مقدار خالی، کوتاه، تماماً فاصله و کلیدهای نمونه شناخته‌شده را رد می‌کند و بدون مقدار معتبر بالا نمی‌آید. هیچ کلید ثابت جایگزینی در JWT یا کپچا استفاده نمی‌شود.

اگر مقدار فعلی تصادفی و امن است آن را حفظ کنید. اگر قبلاً از مقدار نمونه یا کلید عمومی استفاده کرده‌اید، مقدار جدید بسازید و در پنل امن لیارا وارد کنید:

```sh
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

خروجی را در سورس، چت یا ZIP ذخیره نکنید. تغییر secret، همه توکن‌های ورود و مجوزهای رسید قبلی را نامعتبر می‌کند و کاربران باید دوباره وارد شوند. سایر متغیرهای موجود را حفظ کنید. تغییر schema یا migration جدید لازم نیست.

کلید واقعی لیارا از این محیط بررسی یا تغییر داده نشده است. پس از تنظیم secret، ZIP بک‌اند را منتشر کنید.

## بررسی

بیلد بک‌اند و ۴۳ آزمون `npm run test:security` موفق بودند. شش آزمون جدید شامل شروع واقعی AuthModule بدون secret، رد توکن با کلیدهای عمومی، دستکاری نقش، توکن منقضی یا بدون امضا، محدودیت الگوریتم و چرخش کلید هستند. این آزمون‌ها محلی‌اند و وضعیت سرور زنده را تأیید نمی‌کنند. ایراد استفاده مجدد کپچا موضوع جداگانه‌ای است و در این مرحله اصلاح نشده است.

# اصلاح مرحله اول امنیت پرداخت

هر دو ZIP با نام payment-security-fix شامل تغییرات قبلی سایت و اصلاح مسیر پرداخت هستند. ابتدا بک‌اند و سپس فرانت‌اند را در اپ فعلی لیارا بارگذاری کنید. تغییر schema یا migration جدیدی در این مرحله وجود ندارد.

تنظیمات لازم اپ بک‌اند پیش از انتشار:

- `NODE_ENV=production`
- `ZARINPAL_SANDBOX=false`
- `ZARINPAL_MERCHANT_ID`: شناسه واقعی پذیرنده خودتان
- `ZARINPAL_CALLBACK_URL`: آدرس HTTPS واقعی بک‌اند به مسیر `/orders/payment/callback`
- `FRONTEND_URL`: آدرس واقعی فرانت‌اند

تنظیمات موجود اتصال API، دیتابیس و حساب مدیریت را حفظ کنید؛ فایل env نمونه را جایگزین تنظیمات واقعی نکنید. درگاه فاقد تنظیمات صحیح دیگر پرداخت آزمایشی موفق تولید نمی‌کند و با خطا متوقف می‌شود.

پس از انتشار، یک خرید واقعی کم‌مبلغ و بازگشت موفق و ناموفق از درگاه بررسی شود. آزمون‌های محلی با پاسخ ساختگی درگاه انجام شده‌اند؛ تراکنش واقعی در این محیط اجرا نشده است.

سفارش‌های قدیمی دارای Authority با پیشوند `MOCK-` یا شماره مرجع `MOCKREF-` قابل اعتماد نیستند. قبل از آماده‌سازی یا ارسال، پرداختشان را مستقل در پنل درگاه بررسی کنید. اصلاح کد، سفارش‌های قبلی را به‌صورت خودکار حذف یا تأیید نمی‌کند.

این راهنما مربوط به ZIPهای مرحله اول با نام payment-security-fix است. برای اصلاح جدید دسترسی سفارش، بسته‌های order-privacy-fix و راهنمای ORDER-PRIVACY-FIX-README.md را استفاده کنید. فایل‌های latest هم به آخرین بسته تجمیعی اشاره می‌کنند. سایر یافته‌های باز گزارش، از جمله مالکیت سبد، هنوز به اصلاح نیاز دارند.

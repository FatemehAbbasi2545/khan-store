# ارتقای امنیتی Next.js — بسته تجمیعی فرانت‌اند

فایل `khan-store-frontend-nextjs-security-fix.zip` را روی اپ فرانت‌اند فعلی لیارا منتشر کنید. `khan-store-frontend-latest.zip` کپی همین نسخه است. این بسته کل کد فرانت‌اند و تمام تغییرات قبلی، از جمله ورود اجباری برای پرداخت، آیکون‌ها، اینماد، فوتر و صفحات مدیریت محتوا را دارد.

## قبل از استقرار

- نسخه Node.js اپ فرانت‌اند باید حداقل 20.9 باشد؛ Node.js 22 یا 24 توصیه می‌شود. Node.js 18 برای این نسخه قابل استفاده نیست.
- متغیرهای فعلی فرانت‌اند، خصوصاً `NEXT_PUBLIC_API_URL` و `NEXT_PUBLIC_SITE_URL` را حفظ کنید و فرانت‌اند را مجدداً build/deploy کنید.
- `package-lock.json` داخل ZIP است. آن را حذف نکنید؛ نصب قابل تکرار با `npm ci` امکان‌پذیر است.
- بک‌اند و schema در این مرحله تغییر نکرده‌اند. اگر آخرین اصلاحات بک‌اند را منتشر کرده‌اید، بارگذاری دوباره آن لازم نیست. آخرین بسته بک‌اند `khan-store-backend-jwt-security-fix.zip` یا `khan-store-backend-latest.zip` است.

## تغییرات

- Next.js از 14.1.0 به نسخه پایدار 16.4.2 ارتقا یافت.
- React و React DOM به 19.3.1 و typeهای React به شاخه 19 منتقل شدند.
- صفحات محصول، مقاله، کاتالوگ و نتیجه پرداخت با APIهای غیرهمزمان params/searchParams/cookies سازگار شدند.
- محدوده پروژه Turbopack مشخص شد؛ دستور قدیمی و حذف‌شده next lint با دستور مستقل typecheck جایگزین شد.
- شماره نسخه‌های اصلی دقیق و سایر وابستگی‌ها در lockfile ثبت شده‌اند.

## شواهد بررسی

- `npm run test:security`: هر ۶ آزمون موفق بود.
- `npm run build`: بیلد production و بررسی TypeScript موفق بود.
- `npm run test:smoke`: سرور production محلی با API ساختگی اجرا شد؛ مسیرهای حساب، سبد، تسویه، محصول، مقاله، کاتالوگ، کوکی رسید و رد پرداخت مهمان بررسی شدند. این آزمون محلی برای build بدون تنظیمات API واقعی طراحی شده و به پورت آزاد 4000 نیاز دارد؛ روی سرور تولید اجرا نشود.
- `npm audit --omit=dev`: صفر هشدار برای وابستگی‌های اجرایی در زمان بررسی.
- بررسی کامل `npm audit` همچنان ۷ هشدار (۵ زیاد و ۲ متوسط) در وابستگی‌های ابزار ساخت Tailwind/الگوهای فایل و parserهای CSS گزارش کرد. این موارد به معنی باقی‌ماندن نسخه آسیب‌پذیر Next.js نیستند؛ اصلاح آن زنجیره و مهاجرت احتمالی Tailwind باید جداگانه بررسی شود. نتیجه صفرِ audit اجرایی تضمین نبود تمام آسیب‌پذیری‌ها نیست.

پرداخت واقعی، مرورگر و سرور زنده لیارا در این مرحله آزمایش یا به‌روزرسانی نشده‌اند.

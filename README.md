# خان — فروشگاه ممتاز گل و گیاه

پروژه‌ی full-stack «خان» طبق معماری پیشنهادی:
**Next.js (frontend)** + **NestJS (backend)** + **PostgreSQL / Prisma** + **Zarinpal (درگاه پرداخت)**

این نسخه روی هسته‌ی فروشگاه تمرکز دارد: **کاتالوگ، جزئیات محصول، سبد خرید و پرداخت.**
بخش‌های گل مناسبتی، مشاور هوشمند گیاه، باشگاه مشتریان، B2B و پنل مدیریت در فاز بعدی روی همین معماری اضافه می‌شوند.

## ساختار پروژه

```
khan-store/
  backend/     # NestJS API + Prisma schema
  frontend/    # Next.js 14 (App Router) + Tailwind
  docker-compose.yml   # PostgreSQL برای توسعه محلی
```

## پیش‌نیازها

- Node.js 18+
- Docker (برای دیتابیس محلی) — یا هر PostgreSQL دیگری

## راه‌اندازی سریع (محیط توسعه)

### ۱. دیتابیس

```bash
docker compose up -d
```

### ۲. بک‌اند (NestJS)

```bash
cd backend
cp .env.example .env
npm install
npm run prisma:migrate      # ساخت جداول دیتابیس
npm run prisma:seed         # افزودن محصولات نمونه
npm run start:dev           # http://localhost:4000
```

### ۳. فرانت‌اند (Next.js)

```bash
cd frontend
cp .env.local.example .env.local
npm install
npm run dev                 # http://localhost:3000
```

حالا سایت با داده‌های واقعی از دیتابیس (نه داده‌ی نمایشی) روی `http://localhost:3000` در دسترس است.

## نکات مهم پیاده‌سازی

- **انتشار امنیتی نهایی:** هر ۱۶ یافته گزارش اولیه در کد اصلاح شده است؛ `SECURITY-STATUS.md` و `deploy/SECURITY-COMPLETE-README.md` را بخوانید. این نسخه برخلاف ZIPهای قبلی به migration افزایشی نیاز دارد. برای دیتابیس موجود ابتدا `npm run db:baseline` (تطبیق schema و ثبت سابقه) و سپس `npm run db:deploy` لازم است؛ start هیچ تغییر schema انجام نمی‌دهد. دستور start پس از build، فایل `dist/src/main.js` را اجرا می‌کند. Nest CLI قدیمی لازم نیست؛ ساخت با TypeScript انجام می‌شود. برای Node.js هر دو اپ نسخه 22 یا 24 انتخاب شود.

- **نسخه فرانت‌اند:** Next.js 16.4.2 و React 19.3.1؛ برای اجرا Node.js حداقل 20.9 لازم است (Node.js 22 یا 24 توصیه می‌شود). فایل `frontend/package-lock.json` را حفظ و برای نصب قابل تکرار از `npm ci` استفاده کنید. راهنمای انتشار: `deploy/NEXTJS-SECURITY-README.md`.

- **درگاه پرداخت:** پرداخت Mock حذف شده است. فقدان Merchant ID معتبر یا خطای درگاه، پرداخت موفق ایجاد نمی‌کند. برای تولید، `NODE_ENV=production`، `ZARINPAL_SANDBOX=false`، شناسه واقعی `ZARINPAL_MERCHANT_ID` و آدرس HTTPS صحیح `ZARINPAL_CALLBACK_URL` را در لیارا تنظیم کنید. Sandbox فقط با `NODE_ENV=development` یا `test` مجاز است. callback تنها پس از تطبیق Authority با سفارش و تأیید سرور زرین‌پال وضعیت سفارش در انتظار پرداخت را به‌صورت اتمی تغییر می‌دهد؛ callback ناموفق یا تکراری وضعیت نهایی سفارش را تغییر نمی‌دهد. آزمون‌های امنیتی پرداخت: `cd backend` و سپس `npm run test:payment`.
- **سبد خرید مهمان:** انتخاب کالا، افزودن به سبد و مشاهده اقلام و مجموع مبلغ بدون ورود مجاز است. با انتخاب «نهایی کردن سفارش و پرداخت»، ورود لازم می‌شود. ثبت‌نام جدید کاربر را خودکار وارد حساب می‌کند و او را به تسویه‌حساب برمی‌گرداند. توکن سبد هنگام ورود و ثبت‌نام حفظ می‌شود. API ثبت سفارش نیز فقط نشست معتبر مشتری را می‌پذیرد و سفارش را به همان حساب متصل می‌کند.
- **فیلتر هوشمند کاتالوگ:** endpoint مربوطه (`GET /products`) پارامترهای `category`, `search`, `minPrice`, `maxPrice`, `light`, `careDifficulty`, `petSafe`, `airPurifying`, `suitableForOffice`, `sort` را پشتیبانی می‌کند.
- **تصاویر محصولات نمونه:** فعلاً از Unsplash خوانده می‌شوند تا در محیط توسعه بلافاصله قابل مشاهده باشند؛ در تولید باید با تصاویر واقعی محصولات جایگزین شوند (فیلد `images` در جدول `Product`).

## فعال/غیرفعال کردن سفارش آنلاین

### ورود برای پرداخت و حریم خصوصی سفارش

مسیر `GET /orders/:orderNumber` شماره سفارش را به‌تنهایی قبول نمی‌کند؛ توکن معتبر مالک، مدیر یا مجوز مخصوص همان رسید لازم است. پاسخ این مسیر فقط شماره سفارش، وضعیت، مبلغ و مرجع پرداخت است؛ نام، تلفن، نشانی و اقلام مشتری در آن وجود ندارند. جزئیات حساب و پنل مدیر همچنان در مسیرهای دارای کنترل دسترسی خودشان نمایش داده می‌شوند.

ثبت سفارش از فرانت‌اند با مسیر داخلی `POST /api/checkout` انجام می‌شود و نیاز به نشست معتبر مشتری دارد. خود بک‌اند هم درخواست مهمان، توکن منقضی، توکن مدیر یا مجوز رسید را برای ثبت سفارش رد می‌کند. فرم محل و زمان تحویل پس از بررسی معتبر بودن حساب نمایش داده می‌شود. ورود و ثبت‌نام مقصد `/checkout` را حفظ می‌کنند و مقصد خارجی برای بازگشت پذیرفته نمی‌شود.

مسیر ثبت سفارش مجوز رسید هفت‌روزه را در کوکی `HttpOnly`، `Secure` در تولید و `SameSite=Lax` نگه می‌دارد؛ مجوز در URL، localStorage یا پاسخ JSON فرانت‌اند قرار نمی‌گیرد. این کوکی فقط نمایش نتیجه پرداخت را ممکن می‌کند و مجوز ثبت سفارش جدید نیست. رسیدهای قدیمی، مرورگر دیگر یا رسید منقضی‌شده با شماره سفارش تنها قابل مشاهده نیستند؛ مشتری واردشده می‌تواند از «سفارش‌های من» پیگیری کند.

`ADMIN_JWT_SECRET` باید مقدار تصادفی و اختصاصی حداقل ۳۲ کاراکتری داشته باشد. مقدار خالی، کلید پیش‌فرض قبلی و مقدار نمونه رد می‌شوند و بک‌اند با آن‌ها بالا نمی‌آید. تولید مقدار جدید: `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`. مقدار را فقط در تنظیمات امن لیارا وارد کنید؛ تغییر کلید، نشست‌های قبلی و مجوز رسیدها را نامعتبر می‌کند. برای فعال‌شدن این اصلاح، هر دو اپ باید به‌روزرسانی شوند؛ تغییر schema لازم نیست.

آزمون‌ها: در هر دو پوشه‌ی `backend` و `frontend` دستور `npm run test:security` را اجرا کنید.

سبد خرید، تسویه‌حساب و سفارش مناسبتی به‌صورت پیش‌فرض **فعال** هستند. برای توقف موقت سفارش آنلاین، هر دو متغیر زیر را روی `false` قرار دهید؛ برای فعال‌سازی مجدد مقدار `true` را تنظیم کنید.

تنظیمات حالت فعال:
- روی اپ **فرانت‌اند**: `NEXT_PUBLIC_SHOP_ENABLED` = `true`
- روی اپ **بک‌اند**: `SHOP_ENABLED` = `true`
- هر دو اپ رو دوباره دیپلوی کنید (فرانت‌اند حتماً باید دوباره build بشه)

## مجله گل و گیاه

- صفحه‌ی عمومی: `/magazine` — فقط مقاله‌های با وضعیت «منتشرشده» نمایش داده می‌شوند
- مدیریت مقالات از پنل مدیریت → «مجله گل و گیاه»: نوشتن دستی، ویرایش، حذف، و انتشار/پیش‌نویس
- **تولید خودکار پیش‌نویس با هوش مصنوعی (Claude):** هنگام ساخت مقاله‌ی جدید، یک موضوع بنویسید تا عنوان، خلاصه و متن کامل به‌صورت خودکار تولید شود (قابل ویرایش قبل از ذخیره)
- برای فعال‌سازی تولید با AI، در `backend/.env` مقدار `ANTHROPIC_API_KEY` را با کلیدی از [console.anthropic.com](https://console.anthropic.com) پر کنید — بدون این کلید، نوشتن دستی مقاله همچنان کار می‌کند، فقط دکمه‌ی تولید خودکار غیرفعال می‌ماند

## سئو (SEO)

- `sitemap.xml` و `robots.txt` به‌صورت خودکار تولید می‌شن (`/sitemap.xml` شامل صفحه‌ی اصلی، کاتالوگ و تمام محصولاته)
- هر صفحه‌ی محصول عنوان، توضیحات و داده‌ساختاریافته (JSON-LD) اختصاصی خودش رو داره تا در نتایج گوگل بهتر دیده بشه
- روی اپ فرانت‌اند، متغیر `NEXT_PUBLIC_SITE_URL` رو حتماً برابر آدرس واقعی سایت بذارید (مثلاً `https://golekhan.ir`) تا لینک‌های سئو درست ساخته بشن

## پنل مدیریتی (Admin)

آدرس: `/admin` روی همان دامنه‌ی فرانت‌اند (مثلاً `https://khan-frontend.liara.run/admin`)

- ورود با رمز عبوری که در متغیر محیطی `ADMIN_PASSWORD` (روی اپ بک‌اند) تنظیم کرده‌اید — **حتماً قبل از استفاده‌ی واقعی این مقدار پیش‌فرض را عوض کنید.**
- امکانات فعلی: مدیریت محصولات (افزودن/ویرایش/حذف)، مشاهده و تغییر وضعیت سفارش‌ها، داشبورد آمار فروش.
- ویرایش متن صفحه‌ی «درباره ما» از منوی «درباره ما» در پنل (تا وقتی متنی ذخیره نشه، متن پیش‌فرض نمایش داده می‌شه)
- مدیریت دسته‌بندی‌ها، تخفیف‌ها، باشگاه مشتریان و B2B هنوز اضافه نشده‌اند (چون خود آن قابلیت‌ها هنوز ساخته نشده‌اند).
- ورود امن با JWT انجام می‌شود (`ADMIN_JWT_SECRET` را هم حتماً به یک مقدار تصادفی طولانی تغییر دهید).

## دیپلوی مستقیم روی هاست (بدون نصب لوکال، مثلاً وقتی فضای دیسک کم است)

از آنجا که `node_modules` هرگز روی هارد شما ساخته نمی‌شود (روی سرور لیارا ساخته می‌شود)، این روش برای سیستم‌هایی با فضای دیسک محدود مناسب‌تر است.

۱. پوشه‌ی `backend` و پوشه‌ی `frontend` را هرکدام جداگانه فشرده (zip) کنید.
۲. در [liara.ir](https://liara.ir) ثبت‌نام و حساب را شارژ کنید.
۳. از داشبورد: **دیتابیس‌های ابری (DBaaS) → PostgreSQL → ساخت دیتابیس جدید**. بعد از ساخت، اطلاعات اتصال (Host, Port, User, Password, DB Name) نمایش داده می‌شود.
۴. یک اپ جدید از نوع **NodeJS** بسازید، پوشه‌ی زیپ‌شده‌ی `backend` را از طریق «دیپلوی با مرورگر» آپلود کنید.
۵. در تنظیمات همان اپ، بخش **متغیرهای محیطی**، مقادیر `backend/.env.example` را وارد کنید — ولی `DATABASE_URL` را با اطلاعات همان دیتابیسی که در مرحله ۳ ساختید جایگزین کنید.
۶. یک اپ جدید دیگر از نوع **NextJS** بسازید و پوشه‌ی زیپ‌شده‌ی `frontend` را آپلود کنید؛ متغیر `NEXT_PUBLIC_API_URL` را برابر آدرسی که لیارا به اپ بک‌اند شما داد قرار دهید.
۷. برگردید به اپ بک‌اند و `FRONTEND_URL` و `BACKEND_URL` و `ZARINPAL_CALLBACK_URL` را با آدرس‌های واقعی که لیارا صادر کرده به‌روزرسانی و اپ را ری‌استارت کنید.
۸. برای وارد کردن محصولات نمونه، از بخش **کنسول/Shell** اپ بک‌اند در پنل لیارا، دستور `npm run prisma:seed` را یک‌بار اجرا کنید.
